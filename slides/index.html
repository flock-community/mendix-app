The approach

The Mendix app is the specification

1

Capture before you build

Every scenario becomes an end-to-end test that first passes on the Mendix app. The rebuild has to pass the same tests.

2

Reuse, don't redraw

The rebuild compiles Mendix's own theme and renders the same markup, so the same CSS gives the same look.

3

Prove it on every push

CI starts both apps, runs the tests on each and compares the rebuild's screenshots with Mendix's.

The business case

Why do this, and why it is now cheap

Why organisations move apps off Mendix

  • Cost: no platform licences per user and per app
  • No lock-in: code in git runs on any host and cloud
  • Talent: React and TypeScript developers are easy to find
  • Engineering: reviews, unit tests and standard CI/CD
  • Freedom: any UX, library or integration

Why this approach changes the sums

  • AI does the work: the migration costs prompts and review, not a project team
  • Low risk: tests and screenshots prove nothing changed
  • No retraining: users get the app they know
  • Reuse: about 80% of the new code is a library for the next app
  • Gradual: both apps run side by side until cut-over

Pays off for stable apps with many users, and portfolios of similar apps.

Think twice for apps that change weekly, or lean on many Marketplace modules.
