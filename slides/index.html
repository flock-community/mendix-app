Rebuild, don't rewrite

Moving a Mendix app to code

The business case behind it, and a test-first process that keeps the rebuild identical to the original, shown on the TodoApp.

The business case

Why an organisation moves an app off Mendix

€

Platform cost

Licences per user and per app, plus platform hosting, recur every year. An open-source web stack runs on any host.

⇄

Lock-in

Model format, runtime and deployment belong to one vendor. Code in git can move to any cloud or team.

👥

Talent

React and TypeScript developers are a large market. Mendix specialists are a small one.

✓

Engineering practice

Reviewable text diffs, unit tests, typed APIs and standard CI/CD, instead of a binary model file.

✦

Product freedom

Any UX, any library from npm, any integration, and full control over performance and accessibility.

⟳

Own the lifecycle

Upgrade on your own schedule, not when the platform moves to a new major version.

The business case

What usually breaks it, and how this process answers

The rebuild costs too muchAbout 80% of the new code is a reusable library, so each next app only adds its own pages and logic.

The business case

When a rebuild pays off

Strong candidate

  • A stable app with many users, where licences dominate the cost
  • An app that needs UX, integrations or performance the platform makes hard
  • A team that already builds web apps in React or TypeScript
  • Several similar apps, so the library pays back more than once

Think twice

  • Apps that change weekly and are built by citizen developers
  • Apps that lean on many Marketplace modules, workflows or offline sync
  • Short-lived apps, where the rebuild outlives the need
  • Teams without people to own a code base afterwards

The rebuild process

Six phases, with the original as the yardstick

Inventory

Read pages, data, logic and security straight from the Mendix project.

2

Capture behaviour

Write end-to-end tests against the running Mendix app.

3

Carry over the look

Compile Mendix's own theme for the new app.

4

Rebuild page by page

Pages, data, logic and access rules in code.

5

Prove parity

Run both apps in CI and compare tests and screenshots.

6

Cut over

Move data and users, switch traffic, retire Mendix.

4 ⇄ 5 loop per page until the suite is green on both apps and the screenshots match.

Phase 1 · Inventory

Know exactly what you are rebuilding

MendixSQLite

What happens

  • Read the project file: the .mpr is a SQLite index of model units
  • List every page, layout and widget with its settings
  • List entities, validation, microflows, roles and access rules
  • Collect the exact texts users see, from the system texts
In

The Mendix project, no running app needed

Out

An inventory that sizes the rebuild. Here: 1 module, 2 pages, 1 microflow, 1 entity

Done when

Every page and rule has a line in the inventory

Phase 2 · Capture behaviour

The Mendix app writes the spec

PlaywrightTypeScript

What happens

  • Write end-to-end scenarios in the users' terms: sign in, add a todo, filter, page through
  • Find elements by what Mendix renders (mx-name-*), so the same test drives both apps
  • Run them against Mendix until they pass
  • Add screenshots of every key screen
In

The inventory and the running Mendix app

Out

Acceptance criteria as code. Here: 83 tests, 16 of them screenshots

Done when

The suite is green on Mendix

Phase 3 · Carry over the look

No retraining: it looks the same

SassBootstrap (Atlas)

What happens

  • Compile the project's own theme exactly as Mendix builds it
  • Take the widgets' CSS and the icon fonts from the project
  • Reuse the theme's own login page

Phase 6 · Cut over

A switch, not a leap

What happens

  • Copy the data from the Mendix database into the new schema, in a rehearsed script
  • Move user accounts as they are: both apps hash passwords with BCrypt
  • Switch traffic, and keep Mendix read-only for a fallback window
  • Retire Mendix, and keep its last screenshots as the visual baseline
In

A rebuild with green tests and matching screenshots

Out

Users on the new app, and one licence fewer

Done when

The fallback window closes without a rollback
